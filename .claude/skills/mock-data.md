# Mock data (MSW)

`npm run dev:mock` starts the UI with every HTTP request answered from `src/mocks/` instead
of the backend. Use it to design new pages, or to work on any flow while
`wedding-manager-api` is not running.

Nothing in the application branches on the mock: MSW registers a Service Worker that
intercepts `fetch`, so `api.client.ts` and the `*.api.ts` modules run exactly as they do
against the real API. There is no mock/real switch inside `src/services/` — the old
`VITE_USE_MOCK_DATA` / `MockGuestService` seam was removed in favour of this.

## How it is wired

| Piece | Where |
|---|---|
| Flag | `VITE_ENABLE_MSW=true`, set only in `.env.mock`, loaded by `vite --mode mock` |
| Bootstrap | `src/main.tsx` — dynamic `import()` inside the env guard, awaited before the first render |
| Worker | `src/mocks/browser.ts` + `public/mockServiceWorker.js` (generated by `npx msw init`, committed) |
| Handlers | `src/mocks/handlers/*.handlers.ts`, collected in `src/mocks/handlers.ts` |
| State | `src/mocks/mock.db.ts` — mutable, lives as long as the tab |
| Seed data | `src/mocks/fixtures/` |

The dynamic import inside the guard is what keeps `msw` out of the production bundle. Don't
turn it into a top-level import.

## Adding an endpoint

When you add a function to `src/services/`, add its handler here too, or `dev:mock` will log
`[MSW] Warning: intercepted a request without a matching handler` and the page will break in
mock mode only.

1. Pick the file by area: `auth`, `booking` (public), `booking-admin`, `wedding`.
2. Register the path with the `api()` helper — MSW matches absolute URLs, and `api()` prefixes
   `VITE_API_BASE_URL` for you.
3. Read and write `db` from `mock.db.ts` rather than returning a constant, so a page that
   writes and then reads back behaves like the real thing.
4. `await delay()` first, so loading states stay visible.

```ts
http.get(api('/api/admin/things/:id'), async ({ params }) => {
  await delay();
  const thing = db.things.find(t => t.id === Number(params.id));
  if (!thing) return problem(404, 'THING_NOT_FOUND', "No s'ha trobat.");
  return HttpResponse.json(thing);
}),
```

Order matters inside a handler array: MSW matches in sequence, so a literal path has to be
registered before a pattern that would swallow it (`/api/bookings/availability` before
`/api/bookings/:token`).

## Matching the API's wire format

The contract is the API's controllers and DTOs (`wedding-manager-api`,
`src/WeddingManagerApi/Modules/`), not this app's TypeScript interfaces. Getting these wrong
produces a mock that works and a production page that doesn't:

- **camelCase** properties; **enums as their exact C# names**: `"Requested"`, `"GrantAll"`,
  `"Monday"`, `"Admin"`.
- **Two date formats.** `DateTimeOffset` (`startAt`, `endAt`) serializes as `+00:00`, never
  `Z` — use `isoOffset()`. `DateTime` (`createdAt`, `signedAtUtc`, `expiresAt`, …) gets a `Z`
  — use `isoUtc()`. Dates are `YYYY-MM-DD` (`isoDate()`), times `HH:mm:ss`.
- **`price` is a JSON number**, not a string.
- **Status codes are not all 200**: POST creates return 201, deletes and
  `POST .../contract/sign` return 204 with an empty body, but `POST .../confirm` returns 200.
- **Errors are RFC 9457** with `errorCode` and `traceId`. Use `problem(status, code, detail)`,
  and take the code from the `ErrorCode` union in `src/services/error-messages.ts` so the
  Catalan copy is actually exercised. Watch the statuses: the whole `SLOT_*` family is **422**
  except `SLOT_TAKEN`, which is 409. Validation failures use `validationProblem()`.

`src/mocks/availability.mock.ts` is a port of the API's `AvailabilityCalculator`. If the
booking rules change on the backend, that file is what has to follow.

## Seeded data

Fixtures mirror the API's own seed files, so mock mode looks like production:

| Fixture | Source |
|---|---|
| 4 groups, 10 session types with prices and features | `Modules/Sessions/Data/Seed/001_session_catalog.sql` |
| Agenda rows, no buffer, no season window | `Modules/Booking/Data/Seed/002_booking_sessions.sql` |
| Weekly hours; "Exterior" types only Tuesday mornings | `Modules/Booking/Data/Seed/dev_availability.sql` |
| Blocked: `today+3`, and `today+7..+10` | same, relative to today |
| Contract text, 12 sections | `Modules/Booking/Services/ContractTemplate.cs` |
| Wedding `anna-joan`, codes `GARCIA01` / `LOPEZ002` | the retired `MockGuestService` |

Admin login accepts any credentials, and no handler checks the `Authorization` header.
